▼ Backend setup (read once)
This page is wired to a Firestore project so every edit is saved and shared across whoever opens this file. Data lives in the collection patients. The first time this page runs against an empty collection, it seeds it with the 290 records from your sheet. After that, this file is your spreadsheet: edits sync live to Firestore, and re-opening the file (on any device) pulls the current book. The ledger always shows your 290 patients from a local copy first, so it's never blank, but if the sync dot above stays grey or red, edits aren't being saved anywhere permanent, and you need to fix one thing:

Turn on Firestore access. Go to the Firebase console for this project → Firestore Database. If you see a button to create a database, click it and choose test mode (fine for a private tool like this). If a database already exists, open the Rules tab and make sure it allows reads and writes, for example:

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if true;
    }
  }
}

That rule set (open to anyone with the file) is reasonable for an internal tool that isn't linked publicly, but keep the file itself private since anyone with it can read and edit the ledger.
